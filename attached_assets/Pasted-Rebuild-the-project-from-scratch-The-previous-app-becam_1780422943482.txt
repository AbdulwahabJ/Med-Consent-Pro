Rebuild the project from scratch.

The previous app became too large and ERP-like. I want a new simple, modern, focused web app only for consent forms.

Project name:
Consent Portal

Arabic name:
بوابة الموافقات

Main goal:
A simple responsive and adaptive web app used on tablets to create, fill, sign, export, and archive consent PDF forms.

This is NOT:

* Not an ERP
* Not a medical management system
* Not a dashboard system
* Not a complex user management system
* Not a reports analytics system
* Not a branches/specialties/doctors system for now

Core idea:
User logs in or registers.
User creates a new consent.
User selects consent type/template.
The form fields linked to that PDF template appear immediately.
User fills the fields.
Patient signs.
System generates the final PDF.
System saves the PDF under patient consent records.
System shows a success screen.
User can later view previous uploaded/generated consents.

Tech stack:

* React + TypeScript
* Tailwind CSS
* shadcn/ui
* Node.js + Express + TypeScript
* PostgreSQL or simple Replit database if easier
* PDF handling with pdf-lib
* PDF preview with pdf.js if needed
* Signature capture with HTML canvas

New Consent Workflow:
This is the main flow.

Step 1: Select consent type/template

* Show consent templates as modern cards
* User selects one template
* Template examples:

  * موافقة علاج أسنان
  * موافقة خلع
  * موافقة زراعة
  * موافقة تقويم
  * موافقة علاج عصب
* Templates should come from uploaded PDF templates

Step 2: Fill linked fields
After selecting the consent template, show the fields linked to that PDF template immediately in the same flow.

Fields are generated dynamically from the mapped fields of the template.

The user should NOT fill directly on the PDF.
The user fills a clean tablet-friendly form.
Later the system places the values in the correct PDF positions.

Always include basic patient fields:

* Patient name
* File number
* Mobile optional
* National ID optional

Then show the custom mapped fields for that consent template:

* Text
* Multiline text
* Date
* Checkbox

Step 3: Signature

* Patient signs using canvas
* Large signature area
* Clear button
* Confirm signature button

Step 4: Generate PDF

* Generate completed PDF using original uploaded PDF and mapped field positions
* Insert text into correct coordinates
* Insert patient signature into correct position
* Save final PDF automatically
* Show success screen

PDF Field Mapping:
This is a core feature.

User uploads a blank consent PDF.
Then user opens field mapping page.
The PDF is displayed visually.
User can add fields on top of the PDF and save their positions.

Supported field types:

* Patient name
* File number
* Mobile number
* National ID
* Date
* Text
* Multiline text
* Checkbox
* Patient signature

For each mapped field store:

* field key
* Arabic label
* field type
* required true/false
* page number
* x coordinate
* y coordinate
* width
* height
* font size
* display order

Important:
Field mapping is only for setup.
During daily use, user fills a clean form generated from these mapped fields.
The completed PDF is generated after filling.

Handwriting-to-text:
Keep this as an experimental but important feature.

Next to text and multiline fields, add a pen button.

When user clicks the pen button:

* Open a large handwriting canvas modal
* User writes with stylus
* Try to convert handwriting to typed text
* Show recognized text in editable preview
* User can correct the recognized text
* User clicks “إدراج”
* Text is inserted into the field

If handwriting recognition is not supported:

* Show a clear Arabic message
* Allow normal typing
* Do not block the workflow

Do not depend on Gboard or external keyboards.

Signature:
Signature is separate from handwriting.
Signature must be captured using canvas and inserted into the PDF at the mapped signature position.
