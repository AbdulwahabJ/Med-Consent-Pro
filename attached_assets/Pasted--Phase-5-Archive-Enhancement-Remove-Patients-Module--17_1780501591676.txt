ابدأ Phase 5 فقط: Archive Enhancement + Remove Patients Module.

قرار النطاق:
لا نحتاج صفحة المرضى في هذا المشروع.
المشروع هو Consent Portal فقط، وليس EMR أو نظام ملفات مرضى.

لا تضف جدول patients.
لا تضف APIs للمرضى.
لا تضف Patient Details Page.
لا تضف أي جداول جديدة.

نموذج البيانات النهائي يبقى فقط:

* users
* consent_templates
* template_fields
* generated_consents

المطلوب:

1. إزالة قسم المرضى:

* احذف رابط "المرضى" من الـ Sidebar.
* احذف بطاقة "المرضى" من الصفحة الرئيسية.
* احذف أو عطّل أي صفحة Patients إن كانت موجودة.
* تأكد أنه لا يوجد route نشط للمرضى.
* لا تنشئ أي backend endpoints خاصة بالمرضى.

2. تحسين صفحة الموافقات السابقة:
   صفحة "الموافقات السابقة" تصبح هي الأرشيف الرئيسي لكل الموافقات.

أضف بحث واضح في أعلى الصفحة يدعم البحث في:

* اسم المريض
* رقم الهوية / الإقامة
* رقم الجوال
* نوع الإجراء
* اسم الطبيب
* اسم القالب

3. عرض الموافقات:
   اعرض الموافقات في Cards أو Table مناسب للتابلت.

كل بطاقة تعرض:

* اسم المريض
* رقم الهوية / الإقامة إن وجد
* رقم الجوال إن وجد
* نوع الإجراء
* اسم الطبيب إن وجد
* تاريخ الموافقة
* اسم القالب
* تاريخ الإنشاء
* زر معاينة PDF
* زر تحميل PDF
* زر حذف

4. Home Page:
   اجعل الصفحة الرئيسية تحتوي فقط:

* إنشاء موافقة جديدة
* الموافقات السابقة
* قوالب الموافقة

لا تعرض المرضى نهائياً.

5. Backend:

* استخدم endpoints الموجودة للموافقات:

  * GET /api/consents
  * GET /api/consents/:id
  * GET /api/consents/:id/file
  * DELETE /api/consents/:id
* إذا كان البحث أسهل في frontend، نفذه في frontend فقط.
* لا تضف endpoint جديد إلا إذا كان ضرورياً جداً.
* لا تضف جداول جديدة.

6. UX/UI:

* عربي RTL.
* Responsive و Adaptive للتابلت.
* نفس Layout الحالي.
* لا تضف Dashboard.
* لا تضف إحصائيات.
* Empty state واضح:
  "لا توجد موافقات محفوظة بعد. ابدأ بإنشاء موافقة جديدة."

7. Documentation:
   حدّث replit.md ليكون النطاق النهائي:

* Auth
* Consent Templates
* Visual Field Mapping
* Create Consent Wizard
* Generated Consents Archive
* PDF Preview / Download
* WhatsApp Sharing لاحقاً

ولا يحتوي:

* Patients module
* Doctors module
* Roles/Permissions
* Dashboard
* ERP
* Audit Log
* Branches
* Specialties

8. Testing:

* تأكد أن Sidebar لا يحتوي المرضى.
* تأكد أن الصفحة الرئيسية لا تحتوي المرضى.
* تأكد أن صفحة الموافقات السابقة تعرض كل الموافقات.
* اختبر البحث باسم المريض.
* اختبر البحث برقم الهوية.
* اختبر البحث برقم الجوال.
* اختبر البحث بنوع الإجراء.
* اختبر البحث باسم الطبيب.
* اختبر المعاينة.
* اختبر التحميل.
* اختبر الحذف.
* شغل typecheck للـ frontend والـ backend.
* لا تعتبر Phase 5 مكتملة إلا بعد نجاح الاختبارات.

ابدأ التنفيذ الآن وأنهِ Phase 5 بالكامل.
