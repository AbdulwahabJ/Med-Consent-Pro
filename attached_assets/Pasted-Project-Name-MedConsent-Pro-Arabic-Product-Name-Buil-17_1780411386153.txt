Project Name:
MedConsent Pro

Arabic Product Name:
نظام إدارة الموافقات والتقارير الطبية

Build a premium full-stack web application for a dental/medical complex called “MedConsent Pro”.

The system is used to manage medical consent forms, medical reports, PDF templates, doctor-specific templates, patient signatures, document generation, archiving, and secure sharing.

This is not a simple PDF filler. It must be built as a scalable medical workflow system.

Main objective:
Clinic staff should upload blank PDF consent/report templates, map fields visually on the PDF once, then later fill those templates using a clean tablet-friendly dynamic form. After completion, the system generates a final completed PDF with the entered data and signatures placed in the correct mapped positions.

The app will be used mainly on HONOR Android tablets, so the UI must be optimized for touch and stylus.

Important product decision:
Build this as a web application first. Handwriting-to-text should be included as an experimental module, not as a required production feature. The system must remain fully useful even if handwriting recognition is not supported.

Tech Stack:
- Frontend: React + TypeScript
- UI: Tailwind CSS + shadcn/ui
- Backend: Node.js + Express + TypeScript
- Database: PostgreSQL
- ORM: Prisma or Drizzle ORM
- PDF generation/editing: pdf-lib
- Signature capture: HTML Canvas
- Authentication: secure session or JWT-based auth
- File uploads: secure PDF upload handling
- Deployment: Replit-compatible setup

Important Arabic/PDF requirement:
The system must support Arabic RTL text properly in the UI and generated PDF files.
When generating PDFs, embed an Arabic-compatible font such as Noto Naskh Arabic or similar.
Do not rely on standard PDF fonts for Arabic.
Make sure Arabic text is rendered correctly as much as technically possible.
If advanced Arabic shaping is needed, isolate it in a PDF text rendering utility/service so it can be improved later.

18. Design Patterns to Apply

Use repositories for database operations.

Use services for business logic such as generating documents, finalizing forms, validating required fields, and creating audit logs.

Adapter Pattern:

- PDF generation
- File storage
- Messaging/WhatsApp/share
- Handwriting recognition
- Future AI providers

Strategy Pattern:
Use strategy pattern for different field types:
- text
- multiline_text
- date
- checkbox
- dropdown
- signature
- image

Factory Pattern:
Use factories where useful for creating field renderers or PDF field processors.

Policy Pattern:

- canUploadTemplate

- canCreateConsent
- canFinalizeDocument
- canViewArchive

- canManageUsers
