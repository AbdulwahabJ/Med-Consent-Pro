## The Rule
Use `@napi-rs/canvas` to render Arabic field text as transparent PNG images, then embed them in the PDF with `pdfDoc.embedPng` + `page.drawImage`. Do NOT attempt to render Arabic glyphs directly via pdf-lib/fontkit.

**Why:** pdf-lib with fontkit embeds the font correctly but cannot shape Arabic (no ligature/joining logic). Raw Unicode passed to `drawText` produces disconnected isolated letters — unreadable. arabic-reshaper + BiDi reorder was tried but produced overlapping words, wrong x-positions, and spacing issues.

**How to apply:**
1. Use `@napi-rs/canvas` (`createCanvas`, `GlobalFonts`) — Skia engine handles Arabic shaping, BiDi, and ligatures automatically.
2. Register fonts: `NotoNaskhArabic-Regular.ttf` (Arabic) + `DejaVuSans.ttf` (Latin/digits/"/") from `/usr/share/fonts/truetype/dejavu/`.
3. Set `ctx.direction = 'rtl'`, `ctx.textAlign = 'right'`, `ctx.textBaseline = 'middle'`.
4. Font stack: `'NotoNaskh, DejaVuSans, serif'` — DejaVuSans handles "/" and Latin chars that NotoNaskh doesn't cover.
5. Use `RENDER_SCALE = 3` for quality (multiply field pt dimensions by 3 for canvas px).
6. Auto-shrink font if `measureText(text).width > fieldWidth - padding*2`.
7. Render to PNG buffer: `canvas.toBuffer('image/png')`.
8. Embed: `pdfDoc.embedPng(pngBuf)` → `page.drawImage(img, { x, y, width: fieldPt, height: fieldPt })`.

## What NOT to do
- Do not use raw Arabic Unicode with pdf-lib's `drawText` — disconnected letters.
- Do not use arabic-reshaper + bidi-js — overlapping segments, wrong positions.
- Do not use `resvg-js` for text rendering — bbox always empty, text invisible.
- Do not use npm `canvas` (node-canvas) — no native bindings in this environment.
